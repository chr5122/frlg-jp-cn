# 生产模块：火红学习器名称的独立读写入口

这不是首句演示。firered/patches/tm_names.s是项目BUILD0100已采用、现行2.3/BUILD0111仍保留的96B生产源码，逐字节原样公开，来源身份见SOURCE_PROVENANCE.json。

它解决的是学习／遗忘时写入中文招式名与读取显示缓冲的分流：**读写各有独立入口，不以固定LR猜用途**。当前公开代码、ABI前置和名称表已经与2.3/0111核对，但仍不是日版原版到完整汉化的构建包。

## 当前能做的事

### 核对你持有的发布版

Python≥3.10＋GNU Arm binutils，无第三方Python包：

```sh
python3 -B firered/tm_names.py verify --revision 2.3-build0111 --rom /path/to/local-fire-red-2.3.gba
```

只读。完整ROM身份固定为9c92e22573fad9432fe5c64c0c9c810eb504ce73a8660ceff8f7282714b48b6d；不能凭文件名判断。另支持--revision build0100的固定快照。版本不符直接拒绝，不自动放宽哈希。

工具实际编译公开源码，与ROM的96B载荷及四处绑定比较；检查两个stride计算、任务对象大小、355×16B名称表、原生复制函数、对象查找函数、续行代码和完整预留尾部。返回SOURCE_AND_DEPENDENCIES_MATCH只表示这些源码／结构一致，不表示本次已走完游戏学习流程或已通过目标设备。

### 编译生产载荷

```sh
make asm
```

新增build/tm_names.bin，96B；默认链接0x08ED9400，SHA为489ea427b27f709712f56db5232ff42e1fef84e74a13572a7d15f9c47f1928a7。该地址绑定准备好的火红工程，**不是原版空闲地址，也不能用于叶绿**。

## 依赖与接口

| 项目 | 本模块需要的前置 |
|---|---|
| 名称资源 | 0x0871F444处355条名称，每槽16B；整个表哈希固定，公开源码不携带译文 |
| 表步长 | 遗忘路径按16B计算；学习路径由移位组合得到16B索引，不能仍按日版8B寻址 |
| 任务对象 | 原生分配0x28D4B；两块显示缓冲为object+[0x1C0,0x1D0)、+[0x1D0,0x1E0) |
| 原生依赖 | 本版任务对象查找0x0811D8B1、byte-FF复制0x08008901及各自续行入口 |
| 代码预留 | 完整[0xED9400,0xED9600)独占窗，包括守卫／全部FF尾，不能只保留96B |
| 字体与显示 | 已有中文渲染、字宽、菜单及其它生产补丁；本模块不安装这些功能 |

| 入口 | 职责与输入 |
|---|---|
| forgotten_get | 只查询任务对象，返回object+0x1C0，不复制名称 |
| teach_get | 只查询任务对象，返回object+0x1D0，不复制名称 |
| forgotten_write | r0=object+0x77、r1=move×16、r2=名称表，r4=object；复制到+0x1C0，恢复原续行所需r0=object |
| teach_write | r0=object+0x7F、r1=move×16；复制到+0x1D0，回原生续行 |

原生复制函数按字节FF结束。因此一个显示名必须在16B内含结尾FF，F7字形参数内不能含FF；动态控制、占位符、换行也不能混入固定名称槽。本模块不会修改昵称、OT、PID或其它写档数据。

shared/frlg/name_slots.py为后续外部资源接口：pack_names接受调用者有权使用的名称列表和字表，以现有encode/text模块编码／验收；超长、控制符、内嵌FF均拒绝。audit_names核对固定槽但不声称译文正确；不把FF后残留字节当第二个名称。现用表多数槽的结尾后不是全FF，不能为“整洁”清零；打包新表默认FF填充也不代表它能逐字节复现现用表。

## 验证已有构建阶段

在本地拥有精确准备父本时可运行：

```sh
python3 -B firered/tm_names.py build --rom /path/to/prepared-BUILD0099.gba
```

默认内存构建；--output只允许新文件。输入0099 SHA318c1737153e6b4d66d98485ba44e268d65722b87c1b45fd7f981779b4c79c27；输出0100 SHAb4d067c5dc9e00f302a7cfdcafa18fe4a9fac8491a2130b01ad3e1d6654a0de0。四处范围、106B实际差异，零新增分配；只复用已占用的100B，412B原FF尾逐字节保留。新代码96B和其后的4B FF仍属于完整既有预留窗，不可回收。

这条命令是模块自身的固定构建验算，**不是要求普通使用者去寻找一串历史父版**。最终从原版重建时，前序生产模块必须产出这些依赖；目前它们尚未整理齐，不允许修改预期SHA强行把原版送入该阶段。

## 不含游戏文件的CPU测试

```sh
python3 -B tools/check_tm_cpu.py --mgba-prefix /path/to/local/mgba-prefix
```

需本地mGBA开发头／库、C编译器及GNU Arm工具链。本机测试mGBA0.10.5；工具不下载安装依赖，库及其许可证不随仓库打包。

测试用mGBA执行真实96B汇编，但ROM内存、355条名称、对象查找及复制回调全是合成夹具，没有游戏ROM、字库、译文或存档输入。1420个writer用例覆盖355个索引×两种写入×ROM/RAM两种入口；16个getter用例覆盖不同LR（含旧writer标签）。检查精确写入、对象其它字节、R4～R11、SP及栈守卫，并用错误getter偏移证明CPU检查会拒绝。

**合成复制回调不是本次重新执行原游戏StringCopy，RAM入口也不是完整GBARunner3重映射模拟。** 本次CPU测试不等于学习动画、自然游戏流程或设备验收；既有私有历史报告不自动算作本批运行结果。没有新增Delta、GBARunner3或真机支持声明。

统一check会在本机有相应依赖时运行可选编译／CPU测试，缺少依赖明确SKIP。普通Python测试和公开文件检查仍不需要ROM；CI通过不等于所有可选外部测试都运行。

可选CPU测试默认查找本机/opt/homebrew前缀；其它安装位置可通过FRLG_MGBA_PREFIX指定，或直接使用上面的--mgba-prefix命令。
