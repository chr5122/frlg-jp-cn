# 开源路线图

主线是让贡献者能理解、运行和改进项目。历史追溯作为按需查证工具保留，**不再以倒查全部旧FIX作为开源进度指标**。

## 1. 可用的源码仓库

- [x] 共同仓库、MIT边界和第三方来源说明。
- [x] 不携带游戏素材的合成测试与公开文件检查。
- [x] 无make依赖的统一检查入口、入门说明、问题／功能／PR模板。
- [x] 明确说明哪些可运行、哪些仍缺依赖。
- [x] 双版本原版定点修改入口，严格输入／输出身份、原字节、保护窗和新文件写出；不冒充完整汉化构建。
- [x] 自备字形打包／编码字表接口和参数化四图块解码核心；不携带字库素材或原版安装地址。
- [x] 两版原版首句的限定接入实验；明确拒绝通用原生复制尚不支持的FF内嵌字形ID。

## 2. 按成熟功能整理源码

- [ ] 优先整理现行版本需要的中文显示／名称／学习器缓冲／菜单适配源码，逐个说明接口和适用版本。
- [ ] 把私有路径、未固定依赖和运行器前置从功能源码中拆开，保留完整必要台账。
- [ ] 为每个功能提供合成示例、固定输入和反例；适合独立使用的模块优先。
- [ ] 只在来源、ABI或资源身份不明确时追溯历史，不要求先重放每个旧补丁。

## 3. 当前版本的构建流程

- [ ] 定义统一配置和外部资源清单；缺依赖时明确报错，不静默跳过。
- [ ] 在不公开ROM／未授权素材的前提下，整理原版到当前版本所需的最小构建步骤。
- [ ] 补齐允许公开的资源，或提供来源明确的外部资源接口／替代实现。
- [ ] 条件满足后，在隔离目录验证同一组输入能得到相同结果，再发布完整构建说明。

## 4. 持续维护

- [ ] 按实际变更维护面向使用者的源码版本说明，不混用游戏版本号。
- [ ] 保持CI和小范围PR，修复先加反例。
- [ ] 收集设备回归证据；Delta、GBARunner3等未测范围继续明确标注。

没有固定完成日期。完整资源授权和构建依赖未齐之前，不发行“完整可构建包”，也不上传ROM或用历史片段拼装出的不明产物。
