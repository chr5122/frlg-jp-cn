# 依赖与可运行范围

这里区分“测试本仓库”和“构建完整游戏”，不会把缺失资源藏在历史命令里。

| 目标 | 依赖 | 当前结果 |
|---|---|---|
| 合成测试／发布检查 | Python≥3.10，标准库 | clone后可运行，无需游戏文件 |
| ROM身份／token检查 | 同上＋自己持有的精确输入 | 只读，不提供游戏文件 |
| 原版定点修改 | Python＋精确BPRJ/BPGJ Rev0＋自己审核的修改清单 | 校验后可写新ROM；不含完整汉化配方，不需要历史汉化父版 |
| 自备字库打包 | Python＋有权使用的16×16像素JSON | 输出页／字表／哈希，限制12×12有效像素；不读取ROM、不安装 |
| 参数化字形解码核心 | GNU Arm binutils＋调用者提供页表／原生回调与缓冲 | 可编译独立Thumb1载荷；不等于完整前缀／字宽钩子 |
| 原版首句显示实验 | Python＋GNU Arm binutils＋精确原版＋自备字形 | 限定首句14个私有字符；没有通用测宽／扫描或完整译文 |
| 火红学习器生产模块 | Python＋GNU Arm binutils＋固定准备父本／发布件 | 编译96B源码并核对现行2.3依赖；不携带355条译文 |
| 可选学习器合成CPU测试 | GNU Arm＋C编译器＋本地mGBA开发头／库 | 无ROM/SAV输入，执行ROM/RAM入口；不是设备验收 |
| 盒子显示汇编载荷 | GNU Arm binutils＋make | 生成独立载荷，不自动安装进ROM |
| 单字研究实验 | Python＋精确原版BPGJ | 仅实验，不是可游玩汉化 |
| 指定历史增量重放 | Python＋对应精确父版；部分还需本地清单／字表／供体 | 仅支持文档列明的阶段 |
| 当前完整汉化构建 | 当前渲染／编码源码、已授权文本／字库、布局及资源台账、游戏版本适配器和可复现编排 | 尚未完整公开，暂无统一构建命令 |

## 完整构建的待补项

- **编排入口**：按功能组织固定输入、构建顺序、输出身份和失败退出码；不以逐个恢复全部旧FIX为前置条件。
- **中文渲染和资源**：整理必要引擎接口、字形分配及字体来源。能找到或能读取不等于有权公开再分发；未核清者保持外部依赖，必要时改用有明确许可的替代资源。
- **译文输入**：明确来源、署名、许可、格式和版本。工具源码已公开不代表完整译文包已公开。
- **资源台账**：完整继承已占用窗口、守卫和FF尾；不能凭空白重新分配。
- **双版本适配**：火红与叶绿各自绑定实际消费者、调用点和地址。存档与自定义昵称不改。
- **验证入口**：区分纯源码测试、字节核对、受控显示、自然流程、设备验收。没有实测不能填“通过”。

这是一份依赖清单，不是对资源授权的法律结论，也不是已完成完整构建的承诺。[公开范围](PUBLICATION_SCOPE.md)记录当前边界，[路线图](ROADMAP.md)记录推进顺序。
