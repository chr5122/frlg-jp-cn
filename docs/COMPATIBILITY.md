# 验证与兼容性边界

## ARM7／GBARunner3

运行补丁限定 ARM7TDMI／ARMv4T 与 Thumb1。不要引入 Thumb2、BLX 或 `BF00` 当作 ARM7 的 NOP。普通模拟器通过不代表目标硬件兼容。

GBARunner3 可能在镜像／重映射位置执行代码。曾有学习器修复使用固定返回地址分辨“读取名字”与“写入名字”，普通模拟器正常，镜像执行却漏写。后续改为读写独立入口。新增代码必须保持这一约束，并覆盖逻辑地址与镜像执行两种情况。

本仓库的盒子显示源码使用逐调用点入口；火红使用高 ROM 范围内的 Thumb1 BL，叶绿的远目标通过明确的 BX trampoline 调用，不通过返回地址猜用途。它们依赖本版既有 alias，不是任意 ROM 通用补丁。

**NDSL＋GBARunner3 未充分实机验证，不宣称正式兼容。** GBARunner3 联机菜单／交换／对战测试不在当前验证范围；非联机硬件也未认证。Delta、mGBA 和真机必须分别记录，不互相替代。

## 验证分层

- `STATIC`：身份、来源、结构、指针、参数、终止符、容量与资源范围。
- `BYTE_MIGRATION_PASS`：实际差异完全属于获准写入计划。
- `CONTROLLED_DISPLAY`：有记录的受控前置、原生消费追踪与真实截图。
- `NATIVE_STORY`：真实剧情／操作路径；受控显示不能冒称此级别。
- `HARDWARE`：明确的设备、运行器版本及实机验收。

哈希证明文件身份，不证明截图内容真实，也不能从白色框比例证明翻页或关闭。缓冲完整不等于画面不超框；未触发保持 UNKNOWN。

## 已知限制

完整翻译／全联机覆盖并未验收；部分自定义昵称和版本专名按设计保留原样。图鉴的原生箭头与弹窗存在遮挡边界。本仓库测试主要是公共工具合成反例，不覆盖所有游戏场景。
