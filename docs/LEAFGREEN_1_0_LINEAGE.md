# 叶绿早期管线到 1.0：构建清单与末端复现

本批继续从叶绿追溯，而非把火红补丁倒套回来。没有运行旧工程的原地写入器，没有修改正式 ROM、字表或用户存档。公开的是源码及不含正文／图像的身份摘要。

## 一、清单调查结果不是翻译覆盖率

扫描主工程 `analysis/` 顶层 476 份 `*manifest*.json`，加 4 份 `fix*_report.json`，共 480 份记录。输入文件均在扫描结束后再次校验未变。

- 364 份能提取明确的输入与输出 SHA，记为 **声明的哈希边**。
- 116 份缺少可识别的文件名／哈希或需要专用 schema，保持待核。
- 没有把存档、字体或供体 SHA 当成父版 SHA；没有按 FIX 编号、相同文件名或固定偏移自动补边。
- 可选核验了当前 output 中 5 份 GBA 文件；未读取 SAV／state。

**364 不代表重建通过，116 也不代表缺少116次更新。** 这些是记录结构的统计，不是 ROM 数量、翻译条数或完整构建次数。完整摘要见 [LEAFGREEN_1_0_LINEAGE_SUMMARY.json](LEAFGREEN_1_0_LINEAGE_SUMMARY.json)。完整逐条适配结果留在本地审计目录，工具可在持有原工程的机器上重新生成。

逆向追踪最终 1.0 的 SHA，目前能连到 FIX561 合并记录所声明的 FIX558 父本，共 22 份祖先记录。它不是顺序执行 FIX561～583：例如中间跳过部分编号，FIX561 本身也是合并。上游输入／脚本快照仍未全部闭合，不能由这22条宣称原版到1.0已可重建。

## 二、确认的构建方式

| 入口 | 实际读入／操作 | 本批结论 |
|---|---|---|
| `relocate_cn_text.py` | 从 `roms/jp_original.gba` 新建；读本地译文CSV、字表、供体字模和渲染源码 | 原版重建入口，但当前源码已含 FIX348 等后续改动，不能当成原始 Phase8 快照 |
| `build_pallet_complete.py` | 编排字表分配／覆盖审核，再运行重定位器和招式／物品补丁 | 编排器，且会修改字表；不是无副作用的单次旧版重建 |
| `build_pallet_complete_mvp17.py` | 同类编排，另接字宽兼容修复 | 额外依赖不能漏掉 |
| `build_battle_messages_rom.py` | 实际由 `--rom` 读取既有产物，再改写该文件 | 尽管旧说明写“从原版重建”，实际是增量步骤 |
| `build_pokedex_rom.py` | 读取 `--rom`，原版仅作为部分保护区比较输入 | 也是增量步骤，不是独立完整构建 |
| FIX582 / FIX583 | 锁定父版 SHA，再作局部资源／提示文本更新 | 已整理为不覆盖输入的新公开构建器 |

仅有今天的脚本和CSV还不等于拥有历史版本快照。需要进一步锁定每个阶段的资源状态、渲染器版本、字形编号和分配台账，不能把当前大字表塞进旧命令就宣布复现。

## 三、旧路径会漂移，SHA 才是约束

FIX583 原脚本把父版写死为名叫“叶绿日版汉化1.0”的文件，预期 SHA 是 FIX582 的 `d6afc4c9…eb2b`。如今同名文件已经被正式指定为 FIX583，SHA 是 `900b5247…c11c`。

因此照抄旧命令会在父本门禁失败；正确做法是显式提供保留的 FIX582 文件，而不是修改预期 SHA 绕过。公开构建器拒绝已是 FIX583 的输入，也不会按名字猜版本。

## 四、本批新增的可复现末端

`leafgreen/rebuild_1_0_tail.py` 提供两种明确入口：

1. 用户提供准确 FIX582 和本地字表：重建 FIX583，得到最终 1.0 SHA `900b5247f04a30402ae35e3336c398006305efa0b7f01bdc3de1cdc28023c11c`。
2. 用户提供准确 FIX581、原版 BPGJ、美版汉化供体及本地字表：依次构建 FIX582、FIX583。标题资源从用户本地供体读取，仓库不携带标题图块或地图。

所有输入固定大小与 SHA，输出默认只在内存中产生。显式另存时仅接受新文件，拒绝覆盖任何输入。使用现有公共差分门禁，局部改动以外的字节必须保持不变。

### 本次到底验证了什么

- **FIX582→583：** 从真实保留的 FIX582 文件正向构建，与真实保留的最终1.0逐字节一致；15 B 差异、2写入范围、无新指令。
- **FIX581→582：** 主工程及本工作区未找到独立保留的 FIX581。本批从保留的 FIX582 恢复标题旧指针与历史 FF 窗，得到完整 SHA 与记录完全相符的 FIX581 **验证夹具**；再用新构建器及用户本地供体正向构建，与保留的 FIX582 逐字节一致；6209 B 差异、4写入范围。
- 上述夹具没有写出 ROM，也没有公开其字节。**从子版恢复夹具不是独立从原版重建**，不能据此把 FIX581 以前的缺口算作完成。
- 本批没有运行模拟器、做剧情截图或验证硬件。标题导入依赖的旧解压工具现已提炼为带边界检查的独立 LZ77 模块，未引入旧工具所携带的其它资源。

## 五、归档与下一缺口

只读列举了历史压缩归档的目录：有172个GBA成员，名称中的 FIX 编号范围为2～185，没有 FIX581。目录名也有重用的 MVP 编号，不能把同名阶段直接视为源头同一次实验。没有提取或打开其中的存档成员，也没有把归档中的任何 ROM 上传。

下一步应从 FIX558 合并边界往前补证，并给 Phase8／真新镇构建器建立明确的版本化资源输入。原版→FIX581这段仍需源码和资源快照，不用现成ROM的二进制差分冒充完整源码链。第三方资源的公开许可仍未核清。
