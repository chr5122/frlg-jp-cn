# 生产F7测宽分派与下一层字体入口

这批补充现行火红2.3／BUILD0111和叶绿2.3／R89的F7定宽计数、变宽分派、宽度别名及下一层字体入口。编译结果与精确发布件对应区域逐字节一致。它们有固定生产依赖，**不是可直接打入原版的完整测宽库**。

## 已知隐患：叶绿原生回退

2026-10-27已补入[独立R90候选修复入口](#独立r90候选修复)：只改1字节。正式版本仍为R89；其冻结profile继续复现并提示原有隐患，不把候选算成已发布修复。

叶绿的变宽分派拒绝某个F7为私有中文时，会转到0x08005E29。Thumb实际取指地址0x5E28在当前ROM中是一个表项，内容为0x08BC0036，**不是原生F7处理器入口**。火红现行回退使用0x08005E83；两版0x5E82处均有原生处理代码，但不能仅凭这个事实就自动替换叶绿地址。

本批保留现行字节以公开真实实现，并在compile／verify结果的known_issues里明确提示。SELECTED_PRODUCTION_SOURCE_MATCH仅表示所选源码匹配，不表示该回退安全。本批未修改游戏；还需用实际可达的非中文F7文本证明完整调用现场，再另立游戏修复与回归。不要把这份冻结源码当成已修复方案。

## 独立R90候选修复

```sh
# 默认只在内存中重建并核对候选身份：
python3 -B leafgreen/width_fallback.py --parent /path/to/local-R89.gba --original /path/to/local-BPGJ-Rev0.gba
# 可选另存全新路径，拒绝覆盖任何已有文件：
python3 -B leafgreen/width_fallback.py --parent /path/to/local-R89.gba --original /path/to/local-BPGJ-Rev0.gba --output /path/to/new-R90-candidate.gba
```

必须提供精确R89和日版BPGJ Rev0；后者SHA为2957b392dc09fc8df45a660af5493368d7bd378d299862f4cc115998e9da0bf2。工具直接读取该日版分派表，确认处理器是0x08005E82并与父版实际代码一致，再写入带Thumb位的0x08005E83；不从火红地址差推断。

改动限原字面量0xBC010C最低字节29→83；1字节变化，0新指令、0新资源分配，存档代码／slot1和其余整个镜像不变。候选完整SHA为b6648dd18161de6aae734f17923617eea24ccef2175f2446b942df49c6db5be6。编译出的384B修正源必须匹配候选，整枚最终SHA也必须匹配；源码要求显式选择NATIVE_VARIABLE_FALLBACK，无隐式不安全默认值。

本地用完整GetStringWidth及实际ROM代码做受控CPU对照：日版70组、父版130组、候选130组。父版40组到达错误表地址（在执行表数据前停止），候选130组完整返回并恢复ABI；60组非私有结果等于日版，90组未受影响结果等于父版。该批真实ROM／截图及私有运行器不分发，公开CI仅运行合成门禁。

男女原生新游戏命名→缩小→地图回归及像素对照通过。普通游戏里自然触发此隐患的菜单尚未确认：0xF6054两条看似有关的模板会先展开，已排除，不能作为自然故障证据。候选未晋升、未上传，也没有Delta或GBARunner3实机验收。

## 编译、核对与CPU检查

沿用[渲染组件工具](RENDERING_MODULE.md)，无需新装包或下载游戏：

```sh
python3 -B tools/renderer_module.py compile --profile firered-2.3-0111
python3 -B tools/renderer_module.py compile --profile leafgreen-2.3-r89
```

两版现在分别输出7／6个组件，新增部分如下。地址均为ROM文件偏移，不是空间分配许可。

| 组件 | 火红 | 叶绿 |
|---|---|---|
| scanners | 0x7C0048，144B | 0xBC0000，384B（含别名辅助） |
| width_alias | 0x7C065C，36B | 已含于scanners |
| secondary_gate | 0xFF8308，172B，电脑字体 | 0x6DF000，204B，货币／游戏机字体及对齐 |

原生分派表0x5CA0／0x5E28分别绑定火红0x087C0048／0x087C006A、叶绿0x08BC0000／0x08BC0036，表项是保留Thumb状态的偶地址。读核对器检查这些绑定；还核对火红0x7B82A4处转向电脑入口的8B桥接。

可选CPU检查需调用者本地mGBA开发头／库、C编译器与GNU Arm工具：

```sh
python3 -B tools/check_width_cpu.py --mgba-prefix /path/to/local-mgba-prefix
```

不读取任何游戏、字体或存档。C夹具生成16MiB内存镜像、测试流及两个动态堆指针，执行真实编译代码。检查396组火红、1008组叶绿，包括页00／0A／越界、别名、地址边界、两种计数初值和返回地址；确认累加宽度、源指针／计数、栈及相关保留寄存器。两个独立错误字宽产物必须被CPU结果拒绝，不能只靠预期代码哈希。

测试**在所有原生后续入口取指前停止**，包括叶绿的问题回退。状态为SYNTHETIC_TRANSFERS_MATCH，不是完整GetStringWidth、游戏显示、镜像执行或GBARunner3验收；原生续程、字体绘制和本批secondary_gate未做CPU执行。CI没有可选本地工具时会SKIP这一方法。

## ABI与保留的版本差异

- 定宽入口：r4是原字符串基址，r2指向F7后的首操作数字节，r5是字符计数。接受私有ID时r2前移2、r5加1，跳原生后续。火红还把r5截为u8，叶绿这一步不截断；公开测试保留这一差异，不宣称两个函数等价。
- 变宽入口：r4指向F7，r7携带字体，r8累加像素。接受私有ID时r4额外前移2、r8增加相应宽度；原生外层继续处理剩余控制流。
- 两版当前普通别名宽度均为ID0x092A..0x092E取10、0x092F取0，其余合法私有ID取12。空白别名在测宽中为0，不等于字形绘制器返回的宽度为0。
- 火红判断字符串基址：既有ROM文本窗与较宽的EWRAM／IWRAM范围。本批忠实保留，不能据此断言任意RAM文本都是中文。
- 叶绿定宽判断操作数游标，变宽判断F7本身；两者在窗口边缘并非同一谓词。它还识别专用ROM范围、gStringVar、背包及摘要动态分配区。测试显式列出边缘期望，没有复制源码谓词来生成“正确答案”。这些是地址判断，不能充当整条文本的容量证明。
- 叶绿摘要分配路径受前序分支影响：低于gStringVar起点的游标会先转到背包判断，不能把任意低堆地址都算作摘要已识别。合成夹具明确设置摘要拥有者为0x02028000，背包拥有者为0x02010000；不冒充游戏自然分配。

## 字体分流新增部分

火红电脑入口只在模板字体和活动字体都为2、有效电脑对象内前两条显示缓冲、首字节为私有中文、可见长度恰为5时使用小字。保留原有16B计数上限和原生回退。独立导出时保留四个先前包装函数留下的池字，保证PC相对加载与现行字节相同；这四个池字不是新增调用。后续回退0x08FF7835仍待整理。

叶绿货币／游戏机入口检查活动字体0、既有精确游标范围或七个“游标＋字形ID”配对；不是全局缩小“元／枚”。自有配对逻辑随源码公开，不包含所指向的译文。游戏机对齐依赖0x086D5049测量例程；后续字体回退0x08B33A09也仍未公开。

完整小字上下文测量器／包装器、剩余字体链、授权外部资源接口和原版生产安装编排仍未闭合。本批不改变正式游戏版本号，不提供ROM或素材。
